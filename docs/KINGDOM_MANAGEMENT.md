# Kingdom Management

Creating, assigning or clearing a kingdom tag preserves the list's vertical and horizontal scroll position in Results and Comparison. Opening, validating, cancelling or retrying the tag form also keeps the current position. Scrolling while a tag is being saved is retained when the save finishes. Changing the top filter, search, sorting or selected scan starts the new view at the top.

Open the crown in the APES toolbar, or open Kingdom Management under Tools in the Account Operations Center. The feature toggle is in the Kingdom Management section of settings; the Command Palette also includes the tool.

On first use, select **Scan Kingdoms**. APES locks game interaction and reports the ranking and page being scanned. **Cancel scan** or Escape stops the scan. On completion or cancellation, APES restores the original game route, unless another operation has already changed it.

The standalone window starts at up to 920 × 520 pixels, with the compact header, controls, table lettering and row spacing used by SS Scanner. It can be dragged by its header and resized from its bottom-right corner. During scanning, the results window is hidden and a compact progress card sits in a corner, leaving the native statistics table visible behind the interaction lock. The original window size and position are retained when scanning finishes. AOC embedding retains the workspace's fixed sizing.

All action controls, including the crown launcher, use APES-styled `div` elements with `role="button"`, keyboard activation with Enter/Space, and explicit disabled states. Do not replace them with native `button` elements: the game decorates those elements and can interfere with the tool. The regression tests watch for native buttons even during temporary scan and render states.

Native dropdowns use the same explicit visibility and appearance protections as SS Scanner. These cover the Snapshot selector, top Filter selector, every row's Filter selector and both comparison scan selectors, overriding game styles that hide, shrink or disable pointer interaction with selects. Tests include conflicting game-style rules and check computed visibility, size, interaction and option styling; the initial hidden row placeholder remains hidden in the option list.

The scanner opens the statistics window by URL, waits for its native Kingdoms tab, then selects each ranking through the game's native tabs: Population, Size, Attacker, Defender and Victory Points. Selecting the child ranking after its parent is available avoids relying on a combined deep link that may initialize on Victory Points. It returns an already-selected ranking to page 1 using the native first-page control, then advances through the native next-page control. It tolerates transient URL rewrites and omitted default parameters, and verifies page numbers from the rendered pager even when pagination leaves the URL unchanged. It waits for visible tab controls, the active ranking, current page, increasing ranks and stable rendered rows before proceeding. Hidden ancestor tabs are excluded. It joins records by kingdom ID rather than names or ranking positions. Repeated IDs, invalid cells, unfinished pages or incomplete pagination fail the scan instead of saving a partial result. Navigation/loading errors identify the ranking, requested page, observed URL context and rendered page where available.

The table contains population rank, kingdom, king, villages, population, area, player count, average and total attack points, average and total defense points, treasures and victory points. VP and treasure totals are read separately from weekly changes. Click column headings to sort, or search by kingdom or king. A dash means that a kingdom was not listed in that ranking; missing statistics are never converted to zero. The population ranking supplies the displayed rank and king.

The **Filter** column comes before Rank. Choose **Create a Filter** to open the APES form inside the tool, enter a tag such as **Unreal**, then select **Create & assign** or press Enter. The tag is saved and assigned to that kingdom in one action. **Cancel** or Escape closes the form without saving. Invalid tags and storage failures show an inline error and retain the entered text for correction or retry. The same tag becomes available in every row's dropdown; **No filter** clears an assignment. The top **Filter** dropdown shows **All kingdoms** or only kingdoms with the selected tag. Its **Create a Filter** option opens the same form with a **Create filter** action for an unassigned tag, keeping all kingdoms visible so it can be assigned immediately. Tags accept 1–60 characters and reuse existing names regardless of letter case. Filtering combines with search and sorting, works in both Results and Comparison, and shows the number of matching kingdoms.

Tags and kingdom assignments are saved per server alongside snapshot history, keyed by kingdom ID. They carry across new scans and kingdom name changes, including missing kingdoms in Comparison. Assignments are current organizational preferences; historical statistics remain unchanged. Deleting a snapshot does not delete tags. Existing saved snapshots load without migration, backup/restore includes filters, and a failed save leaves the previous assignments intact.

**Results & snapshots** includes a totals row at the bottom of the table, kept visible while scrolling. It sums villages, population, area, players, total attack and defense points, treasures and victory points for the kingdoms currently shown. Selecting a tag, searching, changing assignments or choosing another snapshot updates the totals; sorting does not change them. The average attack and defense cells use total points divided by total players, rounded to at most two decimals. An asterisk marks an incomplete subtotal that excludes unavailable values; its tooltip gives the coverage. A dash means all values are unknown, or an average cannot be calculated from complete point/player counts with at least one player. An empty result has zero additive totals and no averages. Totals do not modify saved snapshots.

Every successful scan creates a separate timestamped snapshot, even when values are unchanged. Snapshots are stored per server using APES storage and included in backup/restore and Storage Manager. Failed or cancelled scans leave existing snapshots intact. History has no automatic deletion limit; individual snapshots can be deleted from Results after confirmation.

The **Comparison** tab follows SS Scanner's selection workflow: choose **Scan A · Earlier**, choose **Scan B · Later**, then select the APES **Compare** action. Scans are listed by date with a scan number and kingdom count. Scan A offers scans with a later scan available; Scan B offers only scans after the selected A. Compare stays disabled until a valid pair is chosen. Changing either selection clears the previous result and requires Compare again. Any chronological pair can be compared, including two older scans. It shows later values and numerical changes, including rank changes, and flags new/missing kingdoms, renames and king changes. Missing kingdoms retain their last known values. A negative rank change indicates an improved rank. A numerical change is only shown when both snapshots contain that statistic.

A scan records statistics sequentially over its displayed start/end interval, rather than at one server instant. Rankings can change during a scan; if this causes duplicated kingdoms across pages, retry the scan. Snapshot metadata retains the scanned page counts and coverage for each ranking.

Run `npm install --prefix tests` and `node tests/kingdomManagement.cjs` for sanitized native-markup and simulated navigation tests. Live-game smoke checks should cover all page counts, cancellation, reopening saved snapshots, and standalone/AOC views on both regular and Halloween servers.
