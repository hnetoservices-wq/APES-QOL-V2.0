# APES Chat Window

An enabled-by-default **Cosmetic Feature**, independent of IGM Enhancer and Clickable Chat Links. It styles the native Messages/IGM conversation window supplied in the user's HTML. The separate public-chat footer retains its original layout.

The window resets the native 55px pane offsets, the reader’s 40% left offset, the history’s 39px top offset and the old avatar/text offsets before applying its flex layout. Outer sizing wrappers fill the available space below the header. The window uses APES parchment backgrounds, a theme-colored header, a compact conversation sidebar and a larger reading area. Native new-conversation, close, conversation selection, folder controls, message content, links and editor/send controls remain the same DOM nodes and retain their Angular bindings. Existing avatars, unread/selected states, timestamps and folder badges are restyled. No replacement chat client, network calls or automatic sending are introduced.

Search matches conversation names and preview text already rendered in the current game list, ignoring case and accents. It intersects existing IGM folder filters instead of changing them. The displayed count reflects currently available matches. Clearing search restores the original list visibility; rows hidden by the game or a folder remain hidden. The existing folder tabs expand to fit the sidebar. When IGM Enhancer is disabled, native conversations and the visual search remain available.

Drag the header to move the window. Drag the bottom-right grip to resize it; a focused grip also supports arrow keys, with Shift for larger adjustments. Initial dimensions are up to 880 × 600 pixels, clamped to the viewport. Position and size survive close/reopen within the page. Viewport resizing keeps the window on screen, and narrower layouts shrink the sidebar. Geometry uses APES-only CSS variables; the game's original inline transform and dimensions are preserved.

The selected conversation uses the actual `chatRoomBody` / `chatBody` scroll hierarchy. The collapsed `openWrite` prompt and expanded `writeArea` remain in normal layout flow; the message area takes the remaining height rather than using the game’s fixed header and 200px editor offsets. Closed conversations retain their native controls and visibility. Message cards use the actual `.line`, `.lineHead` and `.lineBody` nodes, preserve grouped-message headers, formatting, links and hidden load-older/editor nodes. The new-conversation control drops the native inset frame and green diagonal decoration.

The native message editor is not rebuilt when search, filtering, layout or incoming conversation data changes. Draft text, focus, selection, native close/new/send listeners, message formatting and existing links remain intact. New/replaced Angular windows and conversation nodes are observed. Updates are batched per animation frame and the observer is disconnected during its own DOM decoration, avoiding a recurring redraw loop. Removed windows release pointer handlers through an AbortController.

Disable **APES Chat Window** under Cosmetic Features to remove only APES-owned classes, search/branding/empty-state/grip elements and layout variables. Original native nodes, inline styles, controller attributes, drafts and existing IGM tabs remain. No new permissions or stored message data are required.

`node tests/chatWindowStyle.cjs` covers the shell structure provided in the HTML, computed-style conflicts, hidden native/folder rows, accent-insensitive search, counts, identity/listener preservation, late selected-thread insertion, the supplied selected-room hierarchy, native CSS loaded before and after APES CSS, collapsed/expanded/closed conversation layout, disabled native send controls, draft/focus retention, dragging/resizing, viewport bounds, native hidden windows, disable/enable restoration, removal/reopening and observer quiescence. Both committed HTML fixtures contain fabricated conversation data. `chatWindowNativeLayout.css` reproduces the native offset rules offline; the layout regression fails against v159 and passes against v160. Verification also checks the supplied full HTML against the game’s stylesheet locally. JSDOM checks styles and DOM behavior, not browser pixel positions. Live-game verification should include selecting and replying to a real conversation, loading older messages and reopening the window.
